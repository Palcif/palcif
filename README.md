# PALCIF — Palestinian Community in Finland

The public website for the Palestinian Community in Finland (PALCIF): a warm, editorial community and cultural site covering news, events, activities, and blog content in Finnish, English, and Arabic (RTL). Content is authored in a headless WordPress backend and served to this React frontend over WPGraphQL.

Live at [palcif.fi](https://palcif.fi).

## Tech stack

- **React 19 + TypeScript**, built with **Vite**
- **React Router** for routing, **TanStack Query** for data fetching/caching
- **WPGraphQL** against a headless WordPress backend, with types and typed query documents generated by **GraphQL Codegen**
- **react-i18next** for `fi` / `en` / `ar` localization, including Arabic RTL layout
- **react-hook-form + zod** for form validation (contact form submits via **Formspree**)
- **Cloudflare Workers**, deployed with **Wrangler** (`@cloudflare/vite-plugin`)
- Three custom WordPress plugins (see [WordPress backend](#wordpress-backend) below)

## Prerequisites

- Node.js 20+ and npm
- Access to the WPGraphQL endpoint of a PALCIF WordPress backend (local or production)
- A [Cloudflare](https://developers.cloudflare.com/workers/) account with `wrangler` authenticated, for deploys

## Getting started

```bash
npm install
cp .env.example .env   # fill in the values described below
npm run codegen        # generates src/graphql/generated/ from schema.graphql
npm run dev
```

The dev server runs at `http://localhost:5173` by default.

## Environment variables

Set these in `.env` (gitignored; see `.env.example` for the template):

| Variable | Required | Description |
| --- | --- | --- |
| `VITE_WP_GRAPHQL_URL` | Yes | WPGraphQL endpoint the app queries content from, e.g. `https://your-wp-site.com/graphql`. |
| `VITE_FORMSPREE_ID` | Yes, for the contact form | [Formspree](https://formspree.io/) form ID (`https://formspree.io/f/<id>`) that the Contact page submits to. Without it, the contact form shows an error instead of submitting. |

## Available scripts

| Script | Description |
| --- | --- |
| `npm run dev` | Start the Vite dev server. |
| `npm run build` | Regenerate GraphQL types, type-check, and produce a production build in `dist/`. |
| `npm run preview` | Build, then serve the build locally through `wrangler dev` (closest local approximation of the Cloudflare Workers runtime). |
| `npm run deploy` | Build and deploy to Cloudflare Workers via `wrangler deploy`. |
| `npm run lint` | Run ESLint with zero warnings allowed. |
| `npm run typecheck` | Type-check the app without emitting output. |
| `npm run format` | Format `src/**/*.{ts,tsx,css}` with Prettier. |
| `npm run codegen` | Regenerate `src/graphql/generated/` from `schema.graphql` and the query documents in `src/graphql/queries/`. |
| `npm run codegen:schema` | Re-introspect a live WPGraphQL endpoint (using `VITE_WP_GRAPHQL_URL` from `.env`) and refresh `schema.graphql`. |

A Husky pre-commit hook runs `lint-staged`, which lints/formats staged `.ts`/`.tsx` files and formats staged `.css` files.

## Project structure

```
src/
  app/            Root app shell, routing, providers
  pages/          Route-level page components (Home, About, Blog, Activities, …)
  features/       Data hooks and feature-specific components, grouped by domain
  shared/         Cross-cutting components, hooks, utils, types
  graphql/        Query documents (queries/) and generated types/client (generated/)
  i18n/           react-i18next setup and locale files (locales/{fi,en,ar})
  styles/         CSS split by page/component concern, imported via App.css
wordpress-plugins/  Custom WordPress plugins this project depends on (see below)
```

## Internationalization

The site is localized into Finnish, English, and Arabic (`src/i18n/locales/{fi,en,ar}`). Arabic renders right-to-left — when adding or changing layout, verify it holds up in RTL, not just in the default LTR locales.

## WordPress backend

Content (pages, blog posts, highlights, activities, site settings) is authored in WordPress and exposed over WPGraphQL. Highlights, Activities, and Blog posts are unified as native WordPress posts differentiated by category, read through a generic `usePage` / `usePost` / `useSectionPosts` data layer (see `src/features/posts/sections.ts` for the section → category/route mapping).

This repo ships three companion WordPress plugins that the backend depends on (`wordpress-plugins/`):

- **PALCIF Content Sections** — unifies Highlights and Activities into native posts differentiated by category, keeping the category taxonomy shared across Polylang languages.
- **PALCIF GraphQL Polylang Bridge** — adds a `language` filter argument to WPGraphQL connection queries, backed by Polylang's native language support.
- **PALCIF Polylang Per-Language Slugs** — scopes WordPress's slug-uniqueness check per Polylang language, so translated content can keep its natural slug instead of WordPress appending `-2`.

Each plugin's PHP file carries its own header with fuller details. Zipped build artifacts for uploading to WordPress live alongside each plugin's source folder.

GraphQL responses are served as CDN-cacheable **GET** requests and cached at the edge (WPGraphQL Smart Cache + host CDN), with purging tied to WordPress publish/update/delete events; the client also caches via TanStack Query. See inline comments in `src/graphql/client.ts` and `src/app/providers.tsx` for the specific settings.

## Deployment

The app deploys to Cloudflare Workers:

```bash
npm run deploy
```

This builds the app (`codegen` → `tsc` → `vite build`) and runs `wrangler deploy` using the configuration in `wrangler.jsonc`. Ensure `wrangler` is authenticated (`wrangler login`) and that the target Worker's environment has `VITE_WP_GRAPHQL_URL` / `VITE_FORMSPREE_ID` set to production values before deploying.
